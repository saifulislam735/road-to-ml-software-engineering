Domain plan

Primary domain
yourdomain.com — landing page
yourdomain.com/u/username — public profile
app.yourdomain.com — React SPA
api.yourdomain.com — Express API
Why no subdomains per user?
Shared hosting & KVM2 SSL makes per-user subdomain complex to start. Use path-based routing: /u/username. Add custom domains as a Phase 3 feature.

Public pages (no login needed)

/ — Landing
Hero, CTA to register, how-it-works section. Simple, fast.
/u/:username — Public profile
Name, bio, avatar. Anonymous dua input form. Submit button. No login required for sender.
/login & /register
Minimal auth forms. Email + password to start. OTP via email optional Phase 2.

Auth pages (logged-in user)

/inbox — Duas received
List of all anonymous duas. Mark as read. Copy / share to stories. Delete.
/settings — Profile
Edit name, bio, avatar, username. Copy profile link. Toggle: pause receiving duas.
/share — Share kit
Pre-made image for Instagram Story / Messenger. One tap copy link.

Share link mechanic (critical UX)

1
User copies their link
yourdomain.com/u/rafi — one click from /settings or /share
2
Posts to Instagram Story or Messenger Day
Link sticker on IG Story. Platform opens in-app browser on tap.
3
Friend sees the public profile page
No login needed. Simple form: "Send a dua to Rafi anonymously"
4
Owner gets notification
Phase 1: check inbox manually. Phase 2: email/push notification.

Route → Controller → Service → Repository pattern. Controllers handle HTTP in/out, Services hold business logic, Repositories only talk to the DB. Easy to test, easy to scale.

Invalidate refresh token (if used)

User & profile endpoints

GET
/api/users/:username
Public profile — name, bio, avatar. No auth needed.
PATCH
/api/users/me
Update own profile. Requires JWT. Multipart for avatar.

Dua endpoints

POST
/api/duas/send/:username
Anonymous POST. Rate-limited by IP. Body: message text. Returns 201.
GET
/api/duas/inbox
Requires JWT. Returns paginated duas for the logged-in user. ?page=&limit=
DEL
/api/duas/:id
Delete own dua. Requires JWT. Owner-check in service layer.

Database schema (Prisma)

model User {
  id        String   @id @default(uuid())
  username  String   @unique
  email     String   @unique
  password  String
  name      String?
  bio       String?
  avatarUrl String?
  isPaused  Boolean  @default(false)
  createdAt DateTime @default(now())
  duas      Dua[]
}

model Dua {
  id        String   @id @default(uuid())
  message   String
  isRead    Boolean  @default(false)
  createdAt DateTime @default(now())
  ownerId   String
  owner     User     @relation(fields: [ownerId], references: [id])
}

2
Build & push to GHCR

3

Services on KVM2

nginx
Reverse proxy. Port 80→443. Routes api.* to Express, app.* to React static. SSL termination via Certbot.
api
Express app. Port 5000 internal. Depends on postgres + redis. Env injected from .env.prod
web
Nginx serving built React SPA. Port 3000 internal. Static files only.
postgres
PostgreSQL 16. Volume: pg_data. Never exposed to public. Only api can reach it.
redis
Redis 7. Rate limit + session cache. Volume: redis_data. Internal only.
uptime-kuma
Self-hosted uptime monitor. Port 3001. Check API health every 60s. Alert via Telegram.

docker-compose.prod.yml structure

services:
  nginx:
    image: nginx:alpine
    ports: ["80:80", "443:443"]
    volumes:
      - ./infra/nginx:/etc/nginx/conf.d
      - certbot_certs:/etc/letsencrypt
    depends_on: [api, web]

  api:
    image: ghcr.io/yourusername/dua-api:latest
    env_file: .env.prod
    depends_on: [postgres, redis]
    restart: unless-stopped

  web:
    image: ghcr.io/yourusername/dua-web:latest
    restart: unless-stopped

  postgres:
    image: postgres:16-alpine
    env_file: .env.prod
    volumes:
      - pg_data:/var/lib/postgresql/data
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    volumes:
      - redis_data:/data
    restart: unless-stopped

  uptime-kuma:
    image: louislam/uptime-kuma:1
    volumes:
      - kuma_data:/app/data
    ports: ["3001:3001"]
    restart: unless-stopped

Never commit .env.prod to git. Store on KVM2 only. Use GitHub Secrets for CI variables. Set a non-root user in Dockerfiles for production.

Monitoring stack (all self-hosted on KVM2)

Uptime Kuma start here
Simple self-hosted uptime monitor. Checks:
• API /health endpoint every 60s
• Frontend URL every 60s
• Postgres connection via TCP
Alerts: Telegram bot (free & instant).
Prometheus + Grafana Phase 2
Add prom-client to Express. Expose /metrics. Prometheus scrapes it. Grafana dashboards for req/s, latency, error rate, DB pool usage.
Docker logs
docker compose logs -f api for live debugging. Add logging: driver: "json-file" with max-size 10m, max-file 3 to prevent disk fill.
PostgreSQL monitoring
Add postgres_exporter sidecar. Track: active connections, slow queries (pg_stat_statements), DB size over time. Alert if DB > 80% disk.

Alerts to set up on Day 1

1
API down (Uptime Kuma → Telegram)
If /health returns non-200 for 2 consecutive checks → instant Telegram alert
2
Disk space (VPS cron)
Add cron on KVM2: df -h alert if root partition > 80% full. Docker volumes can grow silently.
3
Rate limit hits (Express middleware log)
Log when rate limit is triggered. High frequency = someone trying to spam the dua form.
4
SSL cert expiry (Uptime Kuma)
Uptime Kuma checks SSL cert expiry automatically. Alert 14 days before expiry.

Backup strategy

D
Daily Postgres dump
Cron job on KVM2: pg_dump | gzip → /backups/db_YYYY-MM-DD.sql.gz. Keep last 7 days. Upload to Hostinger file manager or S3-compatible storage.
W
Weekly full backup
Docker volumes snapshot + .env.prod (encrypted). Store offsite.
Ship Phase 1 in 2–3 weeks. Don't add Phase 2 features until real users are using Phase 1.

Phase 1 — Launch MVP

Goal
Working product live on your domain. People can actually send and receive duas.
Features
Register / Login • Public profile page • Anonymous dua form • Inbox to read duas • Copy profile link • Rate limiting on dua form • Basic spam filter (max length, profanity optional)
Infra
KVM2 + Docker Compose + Nginx + SSL + GitHub Actions deploy + Uptime Kuma
Skip
Notifications, image sharing kit, custom domains, reactions — all Phase 2+

Phase 2 — Retention

Features
Email notifications for new duas • Push notifications (PWA) • Share kit: pre-made IG Story image with your link • Reaction emojis on duas (like ❤️ ameen) • Pause receiving duas toggle
Infra
Add email service (Resend or Brevo free tier) • Prometheus + Grafana • Postgres backups automated

Phase 3 — Scale

Features
Custom domains • Dua categories / tags • Public duas feed (opt-in) • Verified badge • Mobile app (React Native) • Analytics dashboard for users
Infra
CDN for static assets • Redis cluster • DB read replicas • Move to managed Postgres if needed

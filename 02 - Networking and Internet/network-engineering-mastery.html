Stage 0 · Foundation

What Is Computer Networking?

The first principles — what networks are, why they exist, and the mental model you'll use forever

A network is any collection of devices that communicate and share resources. Your phone sending a message, a bank processing a payment, a student loading an e-learning page — all of it is networking, and all of it depends on the same core ideas you're about to learn.

🔑 The Expert Mental Model
Every networking concept — routing, switching, firewalls, DNS — solves one problem: getting data from Point A to Point B reliably, securely, and efficiently. Keep this lens on everything you learn.

Network Types by Scale

🏠 PAN — Personal

Range ≤ 10 m. Bluetooth headphones, USB, NFC. Your personal device bubble.

🏢 LAN — Local

Range: building/campus. Ethernet (Cat6A), Wi-Fi 6. 100 Mbps – 10 Gbps. The network you'll design most often.

🏙️ MAN — Metro

Range: city. Multi-building campuses, fibre rings. Metro Ethernet, DWDM.

🌍 WAN — Wide

Range: countries. The Internet. MPLS, SD-WAN, submarine fibre. Connects all other types.

How Student PC-1 Loads a Website — Step by Step

  1. 1
    Student opens browser → types school.edu

    PC-1 (10.1.10.50) checks: Is school.edu's IP in my local subnet 10.1.10.0/24? No → must send to default gateway 10.1.10.1.

  2. 2
    DNS Query — Layer 7 → 3

    PC sends UDP port 53 to DNS server (10.1.40.2). This crosses VLAN boundary: packet goes to gateway 10.1.10.1 (SVI), L3 switch routes it to VLAN 40, arrives at DNS server.

  3. 3
    ARP — Layer 2

    PC doesn't know the gateway's MAC. It broadcasts "Who has 10.1.10.1?". L3 switch responds with MAC AA:BB:CC:11:22:33. Now PC can build an Ethernet frame addressed to that MAC.

  4. 4
    Packet leaves LAN — Layer 3

    DNS resolved. PC builds IP packet to 203.0.113.10 (school.edu server). Frame goes: PC → access switch SW-1 → trunk → L3 switch → firewall → ISP → internet.

  5. 5
    NAT at Firewall

    Firewall replaces source IP 10.1.10.50 with public IP 203.0.113.2 and records the mapping. On the return trip, it reverses this translation.

  6. 6
    Response returns

    Website data arrives at 203.0.113.2, firewall un-NATs it to 10.1.10.50, routes back through switch to SW-1, and PC renders the page. Total time: <100ms.

Network Hardware

Every physical device in a network — what it does, how it differs, when to use it

🔀 Switch — Layer 2 Traffic Director ▶

A switch learns which MAC address is on which port (CAM table), then forwards frames only to the correct port — not to everyone like a hub. Creates collision-free, full-duplex segments.

Key operations: Learn (record src MAC + port) → Flood (unknown dest) → Forward (known dest) → Filter (same-port traffic)

Switch# show mac address-table   # Who's on which port
Switch# show interfaces Gi0/1 status  # Speed/duplex/VLAN
🌐 Router — Layer 3 Path-Finder ▶

A router connects different IP networks using a routing table. It performs NAT, runs routing protocols (OSPF, BGP), applies ACLs, and acts as the DHCP server or relay.

Router# show ip route            # The routing table
Router# show ip interface brief  # Interface status
Router# ping 8.8.8.8 source Lo0  # Test from specific source
🔥 Firewall — Security Gatekeeper L3–L7 ▶

Gen 1 — Packet Filter: Source/Dest IP + port only. Fast but stateless.
Gen 2 — Stateful: Tracks TCP connection state — far more secure.
Gen 3 — NGFW: Deep Packet Inspection, App-ID, User-ID, URL filtering, IPS, SSL decryption. Current enterprise standard.

Leading products: Palo Alto PA, Fortinet FortiGate, Cisco FTD, pfSense/OPNsense (free)

⚡ Layer 3 Switch — Router + Switch in ASIC Hardware ▶

Combines L2 switching and L3 routing in hardware ASICs — routes inter-VLAN traffic at wire speed. Always use at the Distribution layer. Reserve dedicated routers for WAN edge.

Key config: ip routing enables routing. SVIs act as per-VLAN gateways.

Automates IP assignment. Understanding it deeply prevents a whole class of outages.

DORA — The 4 Steps of Getting an IP

VLANs — Logical Segmentation

Create multiple isolated networks on a single physical switch

✅ Why VLANs Are Non-Negotiable
Security: different departments can't see each other's traffic. Performance: broadcasts stay within their VLAN. Flexibility: change a user's department by changing a port — no rewiring.

STP — Spanning Tree Protocol

Prevents Layer 2 loops while keeping redundant links in standby

WITHOUT STP: Broadcast loops forever → switch CPU 100% → complete outage in seconds WITH RSTP (802.1w): Root Bridge elected → blocked ports on redundant paths If primary fails → standby unblocked in 1–3 seconds (vs 30–50s for original STP)

STP Port States (802.1D / PVST+)

StateDurationWhat HappensRSTP Equivalent
BlockingUntil changeReceives BPDUs only — no data framesDiscarding
Listening15 s (Forward Delay)Processes BPDUs, builds active topologyDiscarding
Learning15 s (Forward Delay)Builds MAC table, no user data forwardedLearning
ForwardingStableFully operational — forwards data framesForwarding
DisabledAdmin-downPort shut down — not participating in STPDiscarding

RSTP (802.1w) eliminates Listening state and uses proposal/agreement instead of timers, achieving much faster convergence.

CoreSwitch(config)# spanning-tree mode rapid-pvst
CoreSwitch(config)# spanning-tree vlan 10,20,30,40 root primary
BackupSW(config)#  spanning-tree vlan 10,20,30,40 root secondary
Switch# show spanning-tree summary

Stage 3 · Routing

OSPF — Open Shortest Path First

Industry-standard IGP. Every enterprise network runs OSPF.

OSPF is link-state: every router builds a full topology map (LSDB) and runs Dijkstra's algorithm independently. Changes propagate instantly — convergence in seconds.

Router(config)# router ospf 1
Router(config-router)# router-id 1.1.1.1
Router(config-router)# auto-cost reference-bandwidth 10000  ! 10G ref
Router(config-router)# network 10.1.0.0 0.0.255.255 area 0
Router(config-router)# passive-interface default
Router(config-router)# no passive-interface Gi1/1
Router(config-router)# default-information originate

! OSPF Timer defaults (Ethernet/broadcast): hello=10s dead=40s
! OSPF Timer defaults (Serial/NBMA):       hello=30s dead=120s
! Neighbours MUST match timers or adjacency fails

Router# show ip ospf neighbor     ! Should show FULL state
Router# show ip route ospf        ! OSPF-learned routes

Stage 4 · Network Design

Design Principles & Hierarchy

The 3-tier model and 10 commandments that every good network follows

┌─────────────────────────────────────┐ │ CORE LAYER │ 10/40/100 G, pure speed └──────────┬────────────────┬────────────┘ ┌──────────┴──────┐ ┌──────┴──────────┐ │ DISTRIBUTION │ │ DISTRIBUTION │ L3 switch, ACL, VLAN routing └──┬──────────┬──┘ └──┬──────────┬──┘ ┌───┴──┐ ┌───┴──┐ ┌───┴──┐ ┌────┴──┐ │ACCESS│ │ACCESS│ │ACCESS│ │ACCESS│ L2 switch, VLANs, PoE └──┬───┘ └──┬───┘ └──┬───┘ └───┬───┘ PCs APs PCs APs PCs APs Servers
  1. 1
    Document before you touch anything

    Diagrams, IP spreadsheet, VLAN table. Undocumented networks are liabilities.

  2. 2
    Design for 3–5× current scale

    Use larger subnets than today needs. Re-numbering is 10× the cost.

  3. 3
    Eliminate every single point of failure

    Dual uplinks, redundant core, UPS on IDFs, redundant ISP.

  4. 4
    Segment by security zone without exception

    Guests, users, servers, IoT, VoIP — each its own VLAN with ACL policies.

  5. 5
    Consistent IP addressing scheme

    VLAN 10 → 10.10.10.0/24. VLAN 20 → 10.10.20.0/24. Readable = maintainable.

  6. 6
    Security in every design decision

    SSH only, strong passwords, MFA, 802.1X, disable unused ports. Zero exceptions.

  7. 7
    Monitor from day one

    SNMP, NetFlow, syslog. Finding outages from user complaints = failure.

  8. 8
    Always have a rollback plan

    Test in lab. Change ticket. Pre-written rollback commands. Maintenance window.

  9. 9
    Simplicity is a feature

    The simplest design meeting all requirements is the best design.

Stage 5 · Security

ACLs — Access Control Lists

Ordered traffic filtering — the foundation of network security policy

🚨 Golden Rules
1. Top-to-bottom, first match wins — order matters enormously.
2. Implicit deny-all at end — unmatched traffic is silently dropped.
3. Apply inbound at the VLAN SVI closest to the source.
Router(config)# ip access-list extended STUDENTS_POLICY
Router(config-ext-nacl)# 10 permit udp 10.1.10.0 0.0.1.255 host 10.1.40.2 eq 53
Router(config-ext-nacl)# 20 permit tcp 10.1.10.0 0.0.1.255 host 10.1.40.5 eq 443
Router(config-ext-nacl)# 50 deny ip  10.1.10.0 0.0.1.255 10.0.0.0 0.255.255.255 log
Router(config-ext-nacl)# 100 permit ip 10.1.10.0 0.0.1.255 any
Router(config)# interface Vlan10
Router(config-if)# ip access-group STUDENTS_POLICY in

Stage 6 · Ops

Troubleshooting Methodology

The systematic approach that solves 95% of problems faster than guessing

  1. 1
    Define precisely

    "Internet is broken" ≠ useful. "VLAN 10 users cannot reach 10.1.40.5:443 since 14:30 after a switch config push — all other VLANs fine." That is actionable.

  2. 2
    Scope it

    One user or all? One VLAN? One building? Constant or intermittent? Scope eliminates 90% of the search space.

  3. 3
    Walk OSI bottom-up

    L1: cable/LED. L2: VLAN/trunk/MAC. L3: IP/gateway/route. L4: port open?. L7: DNS/app running?

  4. 4
    One change at a time

    Test, observe, then next step. Changing multiple things simultaneously means you'll never know what fixed it.

  5. 5
    Document root cause

    What was it? Why? How long? Update runbooks, monitoring thresholds, and design decisions to prevent recurrence.

## Windows
ipconfig /all             # IP, MAC, gateway, DNS, DHCP server
ping -n 20 10.1.10.1      # Gateway test
tracert 8.8.8.8           # Hop-by-hop trace
nslookup school.edu       # DNS resolution

## Linux
ip address show ; ip route show
dig school.edu +short
curl -v https://10.1.40.5

## Cisco IOS

Stage 6 · Ops

Automation with Python

One script can configure 100 switches in minutes instead of hours

#!/usr/bin/env python3
# Netmiko — SSH automation for Cisco
from netmiko import ConnectHandler

switches = ['10.1.99.10', '10.1.99.11', '10.1.99.12']
vlan_cmds = ['vlan 10', 'name STUDENTS', 'vlan 20', 'name TEACHERS']

for ip in switches:
    conn = ConnectHandler(device_type='cisco_ios', host=ip,
                          username='netadmin', password='Secret!')
    conn.enable()
    conn.send_config_set(vlan_cmds)
    conn.save_config()
    conn.disconnect()
    print(f"{ip}: VLANs configured ✓")

Lab 1

Basic LAN — Two PCs Communicating

The simplest possible network. Get this solid before anything else.

LAB OBJECTIVE

Make PC-A ping PC-B through a switch

You will understand: IP addresses, subnet mask, default gateway (none needed here — same subnet), and how a switch builds its MAC table.

Topology

PC-A ────────── Switch-1 ────────── PC-B IP: 192.168.1.10/24 IP: 192.168.1.20/24 GW: 192.168.1.1 GW: 192.168.1.1 Mask: 255.255.255.0 Mask: 255.255.255.0

Step-by-Step

! Step 1: Add a switch (Cisco 2960) and two PCs in Packet Tracer
! Step 2: Connect PC-A to Gi0/1, PC-B to Gi0/2 with straight-through cables
! Step 3: Assign IPs on each PC (Desktop → IP Configuration)
!   PC-A: IP 192.168.1.10  Mask 255.255.255.0
!   PC-B: IP 192.168.1.20  Mask 255.255.255.0

! Step 4: Verify from PC-A command prompt
C:\> ping 192.168.1.20      ! Should get 4 replies

! Step 5: On the switch, verify MAC learning
Switch# show mac address-table
!   You should see both PC MACs mapped to Gi0/1 and Gi0/2

! Step 6: Explain what happened:
! - PC-A didn't know PC-B's MAC → ARP broadcast
! - Switch flooded ARP to all ports
! - PC-B replied → switch learned PC-B MAC on Gi0/2
! - Subsequent pings go directly Gi0/1 → Gi0/2
✅ Success Criteria
Ping from PC-A to PC-B: 4/4 replies, 0% loss. show mac address-table shows both MACs. You can explain the ARP process step by step without looking at notes.

Lab 2

VLANs & Trunks

Prove that VLANs isolate traffic — even on the same physical switch

LAB OBJECTIVE

Four PCs on one switch: two in VLAN 10 (Students), two in VLAN 20 (Teachers)

Prove: PC in VLAN 10 cannot ping PC in VLAN 20. Prove: PCs in the same VLAN can ping each other. Add a second switch connected via a trunk — prove VLANs extend across trunk.

! Create VLANs
Switch1(config)# vlan 10
Switch1(config-vlan)# name STUDENTS
Switch1(config)# vlan 20
Switch1(config-vlan)# name TEACHERS

! Assign ports
Switch1(config)# interface Gi0/1   ! PC-A (Student)
Switch1(config-if)# switchport mode access
Switch1(config-if)# switchport access vlan 10

Switch1(config)# interface Gi0/2   ! PC-B (Student)
Switch1(config-if)# switchport mode access
Switch1(config-if)# switchport access vlan 10

Switch1(config)# interface Gi0/3   ! PC-C (Teacher)
Switch1(config-if)# switchport mode access
Switch1(config-if)# switchport access vlan 20

! Configure trunk to Switch2
Switch1(config)# interface Gi1/1
Switch1(config-if)# switchport trunk encapsulation dot1q
Switch1(config-if)# switchport mode trunk
Switch1(config-if)# switchport trunk allowed vlan 10,20

! Verify
Switch1# show vlan brief
Switch1# show interfaces trunk
✅ Success Criteria
PC-A pings PC-B (same VLAN 10): success. PC-A pings PC-C (different VLAN 20): fails. PC on Switch2 VLAN 10 pings PC on Switch1 VLAN 10: success. You can explain 802.1Q tagging.

Lab 4

OSPF Dynamic Routing

Two routers automatically learn each other's routes — and reconverge when a link fails

LAB OBJECTIVE

Three subnets, two routers — OSPF automatically populates routing tables on both

Topology: PC-A (10.1.0.0/24) → Router-1 → (Link 10.0.0.0/30) → Router-2 → PC-B (10.2.0.0/24). Remove the link manually → observe convergence.

! Router-1
R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1
R1(config-router)# network 10.1.0.0 0.0.0.255 area 0   ! LAN
R1(config-router)# network 10.0.0.0 0.0.0.3   area 0   ! Link to R2

! Router-2
R2(config)# router ospf 1
R2(config-router)# router-id 2.2.2.2
R2(config-router)# network 10.2.0.0 0.0.0.255 area 0
R2(config-router)# network 10.0.0.0 0.0.0.3   area 0

! Verify both routers see each other's routes
R1# show ip ospf neighbor          ! State = FULL
R1# show ip route ospf             ! Should see O 10.2.0.0/24
R2# show ip route ospf             ! Should see O 10.1.0.0/24

! Test convergence: shut down the link interface on R1
! Watch 'show ip ospf neighbor' — neighbour disappears after dead interval (40s default)
! Routes via OSPF disappear → network unreachable
! Re-enable interface → reconverges in seconds
✅ Success Criteria
Both routers show FULL OSPF neighbour. PC-A can ping PC-B. Shutdown the link — routing table loses OSPF routes. Re-enable — reconverges. You can explain DR/BDR election.

Lab 5 — Capstone

Full School Network

Build the complete design from Stage 4 — the capstone lab that ties everything together

CAPSTONE LAB — Allow 2–3 Hours

Complete school network: ISP → Firewall → L3 Core Switch → 3 Access Switches → Students, Teachers, Servers

This lab covers: VLANs, trunks, SVIs, DHCP server, DHCP relay, ACLs, NAT, OSPF, and firewall policies — everything from Stages 0–5.

Full Topology

Cloud (ISP) ─── Firewall-1 (203.0.113.2/30 WAN, 10.1.99.254 LAN) │ Trunk (all VLANs) L3-Core-SW (SVIs: V10=.10.1, V20=.20.1, V30=.30.1, V40=.40.1, V99=.99.1) / | \ SW-Floor1 SW-Floor2 SW-Servers │ │ PCs (V10) Servers (V40) AP (V10,V50) DHCP: 10.1.40.3

Build Order

  1. Add and connect all devices (Packet Tracer or GNS3)
  2. Create all VLANs (10, 20, 30, 40, 50, 99) on all switches
  3. Configure trunk ports (switch-to-switch, switch-to-L3-switch)
  4. Configure access ports on floor switches
  5. Configure L3 switch: ip routing, all SVIs, DHCP relay to 10.1.40.3
  6. Configure DHCP server (10.1.40.3) with pools for each VLAN
  7. Configure firewall: NAT, default route, firewall policies
  8. Add ACL on L3 switch: students can't reach admin/servers except Moodle + DNS
  9. Test: Student PC gets DHCP. Pings gateway. Reaches Moodle. Cannot ping Admin PC.
  10. Test: Admin PC can reach everything. Guest PC can only reach internet.
✅ Success Criteria — You Pass When You Can
1. Explain every IP in the network and why it was chosen.
2. Trace a student's packet from click to server response, naming every device it passes through.
3. Add a new VLAN 80 (IoT) with 10.1.80.0/24 from scratch without consulting notes.
4. Teach the OSI model using your network diagram as the visual aid.

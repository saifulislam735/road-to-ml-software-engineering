Module 00Orientation

The landscape: what AI is actually doing in ecommerce

Strip away the hype and AI in commerce reduces to four engines bolted onto a classic web stack: predictive ML (forecasting, ranking, scoring), generative AI (text, images, code), retrieval systems (embeddings, vector search, RAG), and agentic AI (LLMs that take multi-step actions through tools and protocols). Every product you have heard of — Shopify Magic, Amazon Rufus, Salesforce Einstein, Klarna's support AI, Google's Universal Cart — is a composition of these four.

Fig 0.1 — System map. One intelligence layer feeds three surfaces: shoppers, operations, and (new) AI buyer agents.

How this is changing the web itself

Search → conversation

Keyword boxes are being replaced by natural-language and conversational discovery. Product discovery increasingly starts inside ChatGPT, Gemini, Copilot and Perplexity rather than on Google or your homepage.

embeddings + RAG
Pages → answers

The unit of the web is shifting from a page a human reads to structured data an agent consumes. Schema.org markup, product feeds and MCP endpoints are becoming as important as your UI.

structured data, feeds
Clicks → delegated actions

Agents now complete checkouts on behalf of users via open protocols (ACP, UCP, AP2). The "visitor" hitting your API may be software holding a signed payment mandate.

agentic commerce
Static UX → generated UX

Layouts, copy, emails, product imagery and even on-the-fly landing pages are generated per user segment. The site becomes a render target for models, not a fixed artifact.

generative UI
Dashboards → autopilot

Inventory, pricing, ad bidding and fulfillment move from "human reads dashboard, acts" to "model acts, human supervises exceptions." Reported results include 30–40% overstock reduction from forecasting tools.

decision automation
Coding → orchestration

The software behind all of this is increasingly written with AI coding agents (Claude Code, Copilot, Cursor). Engineers shift toward specifying, reviewing and evaluating.

Module 01Method

The pilot → production ladder

Every AI feature in this guide climbs the same four rungs. Knowing which rung you are on tells you what to build, what to skip, and what "done" means. The biggest failure mode is jumping rungs — wiring a prototype straight into checkout traffic.

L0 · Notebook
Proof of concept

One Jupyter notebook or script. Static data export. Goal: prove signal exists. Days, not weeks. No infra.

L1 · Pilot
Shadow / sandbox

A real service behind a feature flag or internal route. Runs on live data, but output is logged, not shown. Build eval set here.

L2 · Limited prod
5–10% traffic A/B

Canary release with guardrails: timeouts, fallbacks to the old system, cost caps, human escalation. Measure business KPI, not model metrics.

L3 · Production
Full rollout + ops

Autoscaled serving, monitoring, drift detection, retraining pipeline, on-call runbook, model/prompt registry. The system is now a product.

Choosing a first pilot

Pick high-volume, low-blast-radius work: product description drafts, background removal, support answer suggestions, search reranking. Visible results, reversible mistakes. Structured rollouts report ~89% success vs ~54% for ad-hoc attempts.

Module 02Customer-facing · production-everywhere

Semantic search & RAG: the new storefront query engine

What it is. Classic ecommerce search matches keywords (BM25 / Elasticsearch). Semantic search embeds every product into a high-dimensional vector so that meaning, not spelling, drives retrieval: "something warm for hiking in rain" finds an insulated waterproof jacket that never contains those words. RAG (Retrieval-Augmented Generation) goes one step further: retrieved products, reviews and policies are stuffed into an LLM prompt so the model can answer ("Which of these fits a 6'2" person?") with grounded facts instead of hallucinating.

How it changed the web. The search bar became a dialogue. Zero-result pages collapse, long-tail queries convert, and the same retrieval index powers your support bot, your PDP Q&A and your agent-facing API. One index, many surfaces.

Implementation — hybrid search API (production shape, L2)

api/retrieval.py + main.py — hybrid search with fusion, filters & fallbackpython
from fastapi import FastAPI
import asyncio

app = FastAPI()

def rrf_fuse(rankings, k=60):
    # Reciprocal Rank Fusion: robust, no score normalization needed
    scores = {}
    for ranked in rankings:
        for rank, pid in enumerate(ranked):
            scores[pid] = scores.get(pid, 0) + 1/(k + rank + 1)
    return sorted(scores, key=scores.get, reverse=True)

@app.get("/search")
async def search(q: str, max_price: float = None):
    try:
        # run dense + sparse in parallel, hard timeout = graceful degrade
        dense, sparse = await asyncio.wait_for(asyncio.gather(
            vector_search(q, top=50, flt={"in_stock": True, "max_price": max_price}),
            bm25_search(q, top=50),
        ), timeout=0.35)
        ids = rrf_fuse([dense, sparse])[:30]
        ids = await cross_encoder_rerank(q, ids)[:12]   # quality jump lives here
        return {"mode": "hybrid", "items": hydrate(ids)}
    except asyncio.TimeoutError:
        # PRODUCTION RULE: search must never 500. Fall back to keyword.
        return {"mode": "fallback_bm25", "items": hydrate(await bm25_search(q, top=12))}

import json, math, asyncio

GOLD = [json.loads(l) for l in open("evals/golden_queries.jsonl")]
# each line: {"q": "warm rain jacket for hiking", "relevant": [142, 87, 530]}

def ndcg(ranked, relevant, k=10):
    dcg  = sum(1/math.log2(i+2) for i, pid in enumerate(ranked[:k])
               if pid in relevant)
    idcg = sum(1/math.log2(i+2) for i in range(min(k, len(relevant))))
    return dcg/idcg if idcg else 0

async def main():
    rec, nd = [], []
    for case in GOLD:
        res = await search(case["q"])
        ids = [it["id"] for it in res["items"]]
        rec.append(len(set(ids[:10]) & set(case["relevant"]))
                   / len(case["relevant"]))
        nd.append(ndcg(ids, set(case["relevant"])))
    print(f"recall@10 = {sum(rec)/len(rec):.3f}   nDCG@10 = {sum(nd)/len(nd):.3f}")
asyncio.run(main())

Pilot → production checklist

  1. L0: export 1k products to CSV, embed with text-embedding-3-small, brute-force cosine search in NumPy. Prove "vibes queries" beat keyword search on 20 hand-written queries.
  2. L1: stand up Qdrant or pgvector in docker-compose; build the 200-query golden set; measure recall@10 and nDCG against current search.
  3. L2: add BM25 + RRF hybrid, cross-encoder rerank, semantic query cache (cached answers for >0.95-similar queries cut LLM calls 30–50%), and the keyword fallback. A/B on 10% traffic; KPI = search→add-to-cart rate, not cosine scores.
  4. L3: nightly re-embed job with index versioning (blue/green index swap), drift alerts on zero-result rate, per-query cost logging. Plan your embedding-model upgrade path before you need it — re-embedding the corpus is a real migration.

Implementation — two-tower model (L2, PyTorch)

recsys/two_tower.py — trainable retrieval modelpython
import torch, torch.nn as nn, torch.nn.functional as F

class Tower(nn.Module):
    def __init__(self, n_features, dim=64):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(n_features, 256), nn.ReLU(),
            nn.Linear(256, dim))
    def forward(self, x):
        return F.normalize(self.net(x), dim=-1)   # unit vectors → cosine

class TwoTower(nn.Module):
    def __init__(self, user_feats, item_feats):
        super().__init__()
        self.user, self.item = Tower(user_feats), Tower(item_feats)

    def loss(self, u_x, i_x, temp=0.05):
        u, v = self.user(u_x), self.item(i_x)        # [B,64] each
        logits = u @ v.T / temp                       # in-batch negatives:
        labels = torch.arange(len(u))                 # diagonal = true pairs
        return F.cross_entropy(logits, labels)

    bought = recently_bought(user_id)
    for c in cands:
        if c.id in bought: continue                       # rule 1: no repeats
        if seen_cat.get(c.payload["category"], 0) >= 3:   # rule 2: diversity

        if len(out) == n + 2: break
    final = [i for _, i in sorted(out, reverse=True)][:n]

Pilot → production checklist

  1. L0: co-occurrence baseline above on an order-history export; sanity-check the top pairs by eye.
  2. L1: log impressions + clicks (you cannot improve what you don't log). Define KPI: rec-slot CTR and attributed revenue/session.
  3. L2: train two-tower on (user, purchased-item) pairs; serve via ANN; A/B against the baseline. Add business re-rank rules (in-stock, category diversity, margin floor).
  4. L3: daily retrain pipeline (Airflow/Dagster), feature store for online user features (Redis/Feast), position-bias correction, cold-start path: fall back to content embeddings from Module 02 for new items.
Classic trap

Offline metrics (recall@k) improving while revenue is flat. Feedback loops — the model recommends what it showed before — are the cause. Always keep a small randomized-exploration slice (e.g. 2% of slots) in production.

Module 04Customer-facing · fastest-growing segment

AI support agents: from chatbot to action-taking agent

import numpy as np, redis
r = redis.Redis()

ARMS = ["free_shipping", "10pct_off", "bundle_deal", "no_offer"]

def choose(segment: str) -> str:
    # Beta(1+wins, 1+losses) per (segment, arm); sample → pick max.
    samples = {}
    for arm in ARMS:
        w = int(r.get(f"b:{segment}:{arm}:w") or 0)
        l = int(r.get(f"b:{segment}:{arm}:l") or 0)
        samples[arm] = np.random.beta(1+w, 1+l)
    return max(samples, key=samples.get)

def reward(segment, arm, converted: bool):
    r.incr(f"b:{segment}:{arm}:{'w' if converted else 'l'}")

def build_features(df):                       # df: date, sku, units, price, promo
    df = df.sort_values(["sku","date"])
    g = df.groupby("sku")["units"]
    for lag in (1, 7, 14, 28):

def traced(feature):
    def deco(fn):
        async def wrap(*a, **kw):
            t0, span = time.time(), new_span(feature)
            try:
                out = await fn(*a, **kw)
                span.set({"tokens_in": out.usage.input_tokens,
                          "tokens_out": out.usage.output_tokens,
                          "cost_usd": cost(out.usage),
                          "model": out.model, "ok": True})
                return out
            except Exception as e:
                span.set({"ok": False, "err": type(e).__name__}); raise
            finally:
                span.set({"latency_ms": int((time.time()-t0)*1000)}); span.end()
        return wrap
    return deco

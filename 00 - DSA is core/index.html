80% of interview problems

These aren't memorized algorithms. They're thinking frameworks — the instant you recognize which pattern fits, the solution becomes obvious.

Brute force aloud first. Then optimize. Never skip straight to clever.
Ask "what data structure makes this operation cheap?" before writing any code.
Clarify: empty input? duplicate values? what if no answer exists?
Time pressure is part of the test. Stay structured, not fast.
The real signal interviewers look for: Can you take an O(n²) brute force and reduce it? Can you choose the right data structure for the constraint? Can you articulate why your solution works? That's it. Dijkstra memorization is useless.
01
HashMap / HashSet
Time: O(n) · Space: O(n) · Converts O(n²) brute force to O(n)
Core Concept

Trade space for time. Store what you've already seen so future lookups are O(1) instead of scanning the whole array again. This is the most commonly-applicable pattern in interviews.

The key question is: what should I store as the key, and what as the value? Once you decide that, the rest writes itself.

Analogy 1 — Library catalogInstead of checking every shelf for a book, you look it up in a catalog (hash) and go directly to the right shelf. One lookup instead of O(n) search.
Analogy 2 — Coat checkYou give your coat (value), get a numbered ticket (hash). Retrieval is instant — you don't search every coat, you go directly to your number.
Analogy 3 — DB indexSELECT WHERE id=5 without index: full table scan O(n). With index (B-tree / hash): O(log n) or O(1). You build the index once, pay O(n) space, save O(n) on every query. Same tradeoff.
Visualization — Two Sum with HashMap
3 Ways to Think About It

Store the complement

Instead of storing what you have, store what you need. target - x is what you need. Check if it's already there before storing x.

Frequency map

When you need to count: Counter(arr) gives {val: count}. Group anagrams, top-K, majority element all use this.

Deduplicate fast

Checking x in set is O(1). x in list is O(n). Always convert to set before membership checks.

Group by property

Sort each word → use sorted word as key → all anagrams land in the same bucket. Any "group by" problem uses this shape.

Recognize When You See
find pair summing to X count frequencies detect duplicate group by property O(n²) nested loop have I seen X? first/last occurrence
DB indexesRedis cachededup queuessession tokens
Edge Cases — Always Check
  • Empty array — return early or handle default
  • All same elements — [3,3], target=6 — same index twice is invalid
  • Negative numbers as keys — Python handles fine, but verify
  • Multiple valid answers — clarify with interviewer before coding
  • No solution exists — return -1, [], or raise? Clarify first
Tips & Tricks
  • Use Counter(arr) or defaultdict(int) to avoid key-existence checks
  • One-pass beats two-pass: can you store AND check in the same loop iteration?
  • Complement trick: store target - x as the key, not x itself
  • Sorted tuple as key: tuple(sorted(word)) is a hashable key for anagram grouping
  • When order matters too, use dict (Python 3.7+ preserves insertion order)
  • For LRU cache type problems, combine dict + doubly linked list (OrderedDict in Python)

02
Two Pointer
Time: O(n) · Space: O(1) · Two variants: opposite ends + fast/slow
Core Concept

Use two indices instead of one to eliminate the need for nested loops. On sorted arrays, start pointers at both ends and move inward — the sorted order tells you which direction to move. For cycles, use a fast pointer (moves 2 steps) and slow pointer (moves 1 step).

Analogy — Squeezing a bagLooking for a pair that adds to target in a sorted array: hold both ends, if sum is too small push the left hand right (increase), if too large push the right hand left (decrease). You never need to check all O(n²) pairs.
Analogy — Tortoise and hare (Floyd's)If you run on a circular track, the faster runner will lap the slower one. If there's no cycle, they never meet. If there is, they do. This detects cycles in O(n) with O(1) space.
Visualization — Opposite Ends (Container With Most Water)
Recognize When You See
sorted array given find pair / triplet in-place removal palindrome check linked list cycle find middle node O(1) extra space
Edge Cases — Always Check
  • Array length ≤ 2 — no work needed or trivially true
  • All same elements — [3,3,3], target=6 — does it return one or all pairs?
  • Sorted descending — two pointer still works but verify direction
  • Fast pointer null check — fast and fast.next before fast.next.next
  • Triplets: sort first, skip duplicates with while l<r and arr[l]==arr[l-1]: l+=1
Tips & Tricks
  • Sort first if not already sorted — two-pointer only works on sorted input (or fast/slow)
  • For 3Sum: fix one element with outer loop, two-pointer for the remaining pair. Total O(n²) beats O(n³) brute force
  • In-place removal: write pointer w marks where to write next valid element. Read pointer r scans ahead
  • Fast/slow meet at cycle entry if you reset slow to head after meeting and move both one step at a time
  • Palindrome: skip non-alphanumeric with while l<r and not s[l].isalnum(): l+=1

03
Sliding Window
Time: O(n) · Space: O(k) · Each element enters and leaves the window exactly once
Core Concept

Maintain a subarray (window) defined by two pointers [l, r]. Expand right to add elements. Shrink left when a constraint breaks. The critical insight: never recompute from scratch — just subtract what left, add what entered.

Two variants: Fixed size (window size = k, slide by 1) and Variable size (expand until constraint breaks, then shrink).

Analogy — Subway train windowYou look out through a fixed-size window as the train moves. New scenery enters on the right, old scenery exits on the left. You don't re-observe everything — just process the change at each edge.
Visualization — Variable Window (Longest Substring, at most K distinct chars)
Recognize When You See
subarray/substring contiguous elements max/min length with condition at most K distinct fixed window of size k longest/shortest that satisfies X
Edge Cases — Always Check
  • Empty string — return 0 or "" immediately
  • All same characters — window expands to full string
  • k=0 or k greater than array length — handle both
  • When shrinking: remove key from dict only if count hits 0
  • Fixed window: prime the first window before starting the loop
Tips & Tricks
  • The window itself stores state (dict, sum, count). Entry adds to state, exit subtracts — never recompute
  • For fixed size k: once window reaches k, slide by removing arr[r-k] before adding arr[r]
  • Deque (collections.deque) is needed for Sliding Window Maximum (#239) — maintains a decreasing monotonic deque
  • For string problems: use array of size 26 instead of dict when chars are lowercase English — faster
  • When condition is "at least K" convert to: answer(at most K) - answer(at most K-1). Classic trick for #930, #992

04
Prefix Sum
Build: O(n) · Query: O(1) · Space: O(n) — precompute once, answer many
Core Concept

Pre-compute cumulative sums so any range sum [l..r] = prefix[r+1] - prefix[l]. Pay O(n) once to build; every subsequent query is O(1). The DB equivalent: precomputed aggregates on indexed columns.

Analogy — Odometer in a carYour odometer always shows total distance from start. To know how far you drove today, subtract yesterday's reading. You don't replay every kilometre — you just subtract two numbers.
Analogy — Running bank balanceprefix[i] = total money deposited up to day i. "How much was deposited from day 3 to day 7?" = prefix[7] - prefix[2]. No need to sum those 5 transactions again.
Visualization
Recognize When You See
sum of subarray [i..j] multiple range queries subarray sum equals K running total 2D matrix region sum pivot index
Edge Cases — Always Check
  • prefix[0] = 0 always — it's the empty prefix, needed for subarrays starting at index 0
  • Negative numbers in arr — prefix still works fine, just check logic
  • Subarray sum = K: use hashmap with seen = {0: 1} initialized before loop
  • 2D prefix: access prefix[r+1][c+1] to stay in bounds with the 1-indexed offset
  • Integer overflow: in Python not an issue; in Java use long
Tips & Tricks
  • Always offset by 1: make prefix size n+1 so prefix[0]=0 handles subarrays starting at index 0
  • Combine with hashmap: "subarray sum = k" → store seen prefix sums → O(n) total, not O(n²)
  • Product prefix: for #238 (product except self), build left-prefix and right-suffix product arrays
  • 2D prefix: p[i][j] = arr[i][j] + p[i-1][j] + p[i][j-1] - p[i-1][j-1] (inclusion-exclusion)
  • Kadane's algorithm is essentially tracking max prefix sum seen so far — recognize the connection

Binary Search
Time: O(log n) · Space: O(1) · Works on sorted arrays AND answer spaces
Core Concept

On any monotonic (sorted) space, eliminate half the possibilities each step. Most people know binary search on arrays. The power move: binary search on the answer itself — if you can write a feasible(x) function that checks if answer ≥ x is possible, you can binary search x over the valid range.

Analogy — Dictionary lookupYou don't scan every page for a word. You open the middle, decide "before or after", repeat. 26 steps maximum for any word, regardless of dictionary size.
Analogy — Binary search on answer (Koko Eating Bananas)"What's the minimum eating speed k?" Instead of trying every k, check: "Is speed k feasible?" — this check is O(n). Binary search k from 1 to max_pile. O(n log max) beats O(n²) brute force.
Visualization — Find first occurrence of target
Recognize When You See
sorted array find boundary / first/last minimize the maximum can X achieve Y? (binary on answer) DB indexed column lookup rotated sorted array
Edge Cases — Always Check
  • Off-by-one: use l <= r for find-exact, l < r for find-boundary
  • Mid overflow: use mid = l + (r - l) // 2 (critical in Java, fine in Python)
  • Empty array — check before entering loop
  • Rotated array: determine which half is sorted first, then decide direction
  • All same elements — mid == target but need to keep searching for leftmost
Tips & Tricks
  • For "find leftmost": when arr[mid]==target, save ans=mid but continue with r=mid-1 to keep searching left
  • For "search on answer": write feasible(k) first. Then binary search k. Range is usually [1, max_value]
  • Rotated array: arr[l] <= arr[mid] means left half is sorted. Check if target is in that sorted half
  • If asked "how many valid answers", think about binary searching the boundary between valid/invalid
  • Python: bisect.bisect_left(arr, x) gives leftmost insertion point — use as shortcut

Stack / Monotonic Stack
Time: O(n) amortized · Space: O(n) · Each element pushed and popped exactly once
Core Concept

A stack gives O(1) access to the most recently seen element. A monotonic stack maintains elements in sorted order — whenever a new element violates the order, pop until it's restored. As elements are popped, they've found their "answer" (next greater/smaller).

Analogy — Browsing historyBrowser back button = stack. The page you just came from is always at the top. Nested calls in code execution = call stack. Most recent is always accessible in O(1).
Analogy — Monotonic stack as a bouncerBouncer only lets in shorter people (decreasing stack). When a taller person arrives, kick out everyone shorter — those short people just found their "next taller person" the moment they got kicked out.
Visualization — Daily Temperatures (Next Warmer Day)
Recognize When You See
matching brackets / valid parens next greater element next smaller element wait time / temperatures largest rectangle decode nested strings undo / call stack behaviour
Edge Cases — Always Check
  • Stack empty check before popping — if stack: first
  • Remaining elements in stack after loop — they have no "next greater", ans stays 0
  • Circular array (#503): run the loop twice (or once with index % n)
  • Equal elements: decide if "strictly greater" or "greater or equal" matters for your problem
  • Parentheses: store the index, not just the char — needed to compute substring length
Tips & Tricks
  • Monotonic decreasing: pop when new element is GREATER → you're finding "next greater element"
  • Monotonic increasing: pop when new element is SMALLER → you're finding "next smaller element"
  • Always store indices, not values — you need index to compute distance or update an answer array
  • Histogram (#84): extend each bar as far left as possible using monotonic stack. Classic hard problem, high frequency
  • For "min stack" (#155): maintain a second stack tracking the current minimum alongside the main stack

BFS / DFS on Graphs & Trees
Time: O(V+E) · BFS → shortest path · DFS → all paths, cycle, ordering
Core Concept

BFS uses a queue — explores level by level. Use when you need the shortest path in an unweighted graph, or want to find something "nearest".

DFS uses a stack (or recursion) — goes deep before backtracking. Use for: all paths, cycle detection, topological sort, connected components.

Analogy — Ripple vs divingBFS = throw a stone in water. Ripples expand evenly outward — everything at distance 1 before distance 2. DFS = dive deep into one path before surfacing and trying the next branch.
Analogy — npm install (topological sort)Package A needs B before installing. B needs C. DFS detects this order (post-order = finish time = install order). If DFS finds a back-edge, it's a circular dependency = cycle error.
Visualization — BFS vs DFS traversal order
Use BFS When
shortest path (unweighted) nearest X to Y level-order traversal minimum steps word ladder / state graph
Use DFS When
all paths cycle detection topological sort connected components flood fill / islands
Edge Cases — Always Check
  • Mark visited BEFORE adding to queue (not after dequeue) — prevents duplicates
  • Disconnected graph — outer loop over all nodes to cover all components
  • Grid bounds — check 0 <= r < rows and 0 <= c < cols before accessing
  • Empty graph / single node — handle before entering traversal
  • Cycle detection: use colors — white(unvisited), gray(in-stack), black(done)
Tips & Tricks
  • Multi-source BFS: start with ALL sources in queue at once — "rotting oranges", "0-1 matrix"
  • Grid as graph: 4 directions = dirs = [(0,1),(0,-1),(1,0),(-1,0)]
  • BFS level tracking: either store (node, depth) tuples, or count queue size at level start
  • Topological sort (Kahn's): use in-degree array. Add nodes with in-degree=0 to queue. Reduce neighbors' in-degree when popped
  • Cycle in directed graph (DFS): if you reach a node that's in the current DFS stack (grey), it's a cycle

1D Dynamic Programming
Time: O(n) · Space: O(n) or O(1) with optimization · Overlapping subproblems
Core Concept

DP applies when a problem has overlapping subproblems — the same smaller problem appears multiple times. Instead of solving it repeatedly (exponential recursion), store the result once.

Two approaches: Memoization (top-down: recurse + cache) and Tabulation (bottom-up: fill table iteratively). Both give same complexity; tabulation is usually cleaner.

Analogy — Staircase choicesYou're at step n. You got there from step n-1 or n-2. The number of ways to reach step n = ways(n-1) + ways(n-2). You don't re-count — you look up the answer you already computed.
Analogy — House robber as business problemCan't take two adjacent quarters' revenue. At each quarter: max(skip and take prev, take this + two-quarters-ago). A real quarterly planning problem with DP shape.
Visualization — House Robber: build dp table
How to Derive the Recurrence (Framework)
1. Define dp[i] clearly in English → 2. Find transition: dp[i] depends on which previous? → 3. Base cases: dp[0], dp[1] → 4. Answer: dp[n] or max(dp)

Count ways

dp[i] = sum of ways to reach i. Climbing stairs: dp[i] = dp[i-1] + dp[i-2]

Optimize value

dp[i] = max/min value achievable. House robber, coin change. Choose: take it or skip it.

Boolean feasibility

dp[i] = can I achieve X? Word break: dp[i] = any dp[j] + word[j..i] valid.

Space optimize

If dp[i] only uses dp[i-1] and dp[i-2], ditch the array. Use two variables.

Recognize When You See
number of ways to reach X minimum cost / steps maximum profit can you achieve X? choices at each step overlap optimal substructure
Edge Cases — Always Check
  • Array of length 0 or 1 — dp may not have index 1; handle separately
  • Initialize dp table with correct defaults (0 for count, inf for min, -inf for max)
  • Coin change: if no solution, dp[amount] stays inf — return -1, not inf
  • LIS: answer is max of entire dp array, not just dp[n-1]
  • House Robber II (circular): run House Robber on [0..n-2] and [1..n-1], take max

Sort First / Interval Problems
Time: O(n log n) dominated by sort · Most interval problems are O(n) after sorting
Core Concept

Sorting converts a chaotic problem into a structured one where greedy logic works. Most interval problems become trivial once you sort by start time: adjacent intervals either overlap (merge them) or don't (keep both).

The principle: after sorting, you only need to compare each interval with the last one in your output — you never need to go back further.

Analogy — Calendar schedulingYou have 10 meetings with start/end times. Sorted by start: scan once, merging any that overlap with the last meeting. O(n) scan after O(n log n) sort. No need to compare every pair.
Visualization — Merge Intervals
Recognize When You See

Edge Cases — Always Check
  • Single interval — return as-is
  • Touching intervals: [1,4] and [4,6] — do they merge? Clarify with interviewer (<= vs <)
  • Fully contained: [1,10] swallows [3,5] — use max(last_end, end) not just end
  • Insert interval: three regions — before, overlapping, after. Process each separately
  • Meeting rooms II: need min heap to track end times, not just sorting
Tips & Tricks
  • Always sort by start time for merge problems; sort by end time for activity selection / greedy scheduling
  • Meeting Rooms II (min rooms): use a min-heap of end times. If earliest end < current start, reuse that room
  • Custom sort: sort(key=lambda x: (x[0], x[1])) for tuple comparison; or functools.cmp_to_key for complex comparisons
  • Non-overlapping intervals (#435): greedy — always keep the interval with the earlier end time (leaves more room for future)
  • Largest Number (#179): sort by comparing concatenated strings — b+a vs a+b to decide order

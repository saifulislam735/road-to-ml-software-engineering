Key insight: The broadcaster never talks directly to viewers. They push to your server, your server converts to HLS, and viewers pull those HLS files via HTTP — the same way a browser loads any webpage.

What each stage does

🎥

OBS / Encoder

Captures screen + mic, compresses with H.264 codec, sends over RTMP. Free, open source software.

🔄

RTMP ingest

Real-Time Messaging Protocol. TCP-based, port 1935. OBS → your server. Very stable, industry standard.

⚙

Nginx + nginx-rtmp

Your media server. Receives the RTMP stream and triggers FFmpeg to process it.

📺

FFmpeg transcode

Converts one RTMP stream into multiple HLS quality levels (360p, 720p, 1080p) simultaneously.

📄

HLS segments

Video chopped into 2–6 second .ts files. A .m3u8 playlist tells the player which file to fetch next.

🌎

CDN delivery

Content Delivery Network. Caches your HLS files at servers near viewers globally. Reduces latency.

Every streaming system is built on these four protocols. Know them cold.

00:00:00SYSTEMWaiting for broadcaster to connect...

What it is: TCP-based protocol developed by Macromedia (now Adobe) for sending audio/video from an encoder to a media server.

Port: 1935 (you must open this on your VPS firewall)

Used for: Ingest only — OBS → your server. Never viewer → browser delivery.

Why TCP? RTMP uses TCP which guarantees every packet arrives in order. Good for reliable ingest. Slightly slower than UDP but acceptable for the upload side.

What you configure:

nginx configRTMP ingest endpoint
# In nginx.conf — the RTMP block
rtmp {
  server {
    listen 1935;        # Open this port on your firewall
    chunk_size 4096;

    application live {
      live on;           # Enable live streaming
      record off;        # Don't record to disk (for now)
    }
  }
}

OBS settings: Server = rtmp://YOUR_SERVER_IP/live, Stream key = your unique key

What it is: Apple's streaming format. Video is split into small segments, delivered over regular HTTP. Works in all browsers via HLS.js.

How it works: FFmpeg chops video into 2–6 second .ts segment files. A .m3u8 playlist file lists the latest segments. Player fetches the playlist every few seconds, then fetches the new segments.

Why HTTP? Regular port 80/443. Passes through firewalls. CDNs cache it. No special client needed.

Latency: 15–30 seconds by default. Can be reduced to ~5s with Low-Latency HLS (LL-HLS). Good enough for most sports streams.

What it is: A persistent connection between browser and server that both can send messages over at any time. Unlike HTTP where client always initiates.

Used for: Live chat, viewer count updates, stream status, real-time notifications.

How it starts: Starts as an HTTP request, then upgrades ("handshake") to a WebSocket connection.

What it is: Browser-to-browser (or browser-to-server) real-time communication using UDP. Sub-1 second latency.

When to use: Interactive streams where latency matters — betting streams, interactive sports, live Q&A where you react to audience in real time.

When NOT to use: General streaming. WebRTC doesn't scale to thousands of viewers without an SFU (Selective Forwarding Unit) server like Mediasoup or Livekit. Complex to implement.

Your plan: Start with HLS (easy, scalable). Add WebRTC later for specific low-latency use cases.

Video fundamentals

Codecs, bitrates, and adaptive streaming — what they mean and why they matter.

Codecs

A codec is an algorithm that compresses video. Raw video is enormous — a 1-minute 1080p clip is ~10GB uncompressed. Codecs shrink it to a manageable size by throwing away data the human eye can't perceive.

CodecCompressionCPU costBrowser supportLicenseUse when
H.264 / AVC Good Low 100% universal Patented Default choice. Always.
H.265 / HEVC 50% better Medium ~85% browsers Royalty fees Better quality, but skip for now
AV1 Best Very high Modern browsers Free, open Future — not yet for live
VP9 Good Medium Chrome/Firefox Free, open YouTube uses it, but skip
Your starting codec: H.264. It works everywhere, FFmpeg handles it by default, and OBS outputs it by default. No configuration needed.

Bitrate

Bitrate is how much data per second your stream uses. Higher bitrate = better quality but more bandwidth cost and more CPU to encode.

ResolutionFPSRecommended bitrateUpload needed
360p30400–800 Kbps~1 Mbps
480p30800–1,500 Kbps~2 Mbps
720p302,000–3,000 Kbps~4 Mbps
720p603,000–4,500 Kbps~6 Mbps
1080p304,000–6,000 Kbps~8 Mbps
1080p606,000–9,000 Kbps~12 Mbps

Keyframe interval = 2 is mandatory for HLS. If OBS sends keyframes every 10 seconds, your HLS segments can't be split cleanly, and viewers will see artifacts and buffering.

Adaptive Bitrate (ABR)

ABR means your server creates multiple quality versions of the stream (e.g. 360p, 480p, 720p, 1080p). The player automatically switches between them based on the viewer's internet speed. This is what Netflix, YouTube, and Twitch all do.

How DNS works

DNS (Domain Name System) converts yoursite.com into your server's IP address (e.g. 65.21.44.100). Without DNS, viewers would have to type your IP address.

RecordWhat it doesYour example
A record Maps domain/subdomain → IPv4 address @ → 65.21.44.100 (main site)
A record Maps subdomain → server IP rtmp → 65.21.44.100 (ingest server, DNS-only!)
CNAME Alias one domain to another www → yoursite.com
MX record Where to deliver email Point to Mailgun or Resend later
Critical: Your rtmp.yoursite.com A record must be set to DNS-only (gray cloud in Cloudflare). RTMP does NOT work through Cloudflare's HTTP proxy. Only web traffic goes through Cloudflare's proxy.

Why each choice

Next.js gives you Server-Side Rendering (SSR) out of the box. For a streaming site this matters because search engines need to crawl your stream pages. A plain React SPA (Single Page App) returns empty HTML to Google bots — your streams won't appear in search results.

Next.js also handles routing, API routes (you can write backend endpoints inside the same project), image optimization, and has the best deployment story (Vercel or self-hosted).

Nginx-RTMP: Open source, free, well-documented, works with any Nginx server. Best starting point. Limited to single-server without extra work.

SRS (Simple Realtime Server): Better performance than Nginx-RTMP, supports LL-HLS, cluster mode. Good step up when you outgrow Nginx-RTMP.

Wowza: Commercial, expensive ($95/mo), but enterprise-grade. Not for indie projects.

Your choice: Nginx-RTMP to start. You can migrate to SRS when you need to scale.

Your streaming data is relational: users have stream keys, streams belong to channels, subscriptions belong to users. This is textbook SQL territory — relationships, joins, transactions.

MongoDB is great for unstructured data but adds complexity without benefit here. Use PostgreSQL. It's free, battle-tested, and Supabase gives you a managed PostgreSQL instance with a generous free tier.

Use Redis separately for high-frequency real-time data: viewer counts, live chat messages, stream status. Redis is an in-memory store — extremely fast but not for permanent data.

Cloudflare Stream: Easiest. $5/1000 min stored, $1/1000 min delivered. Handles transcoding too. No server needed. Best for launching quickly.

BunnyCDN: Much cheaper at scale. ~$0.01/GB egress. You self-transcode with FFmpeg and push HLS to BunnyCDN. More control, lower cost at volume.

AWS CloudFront: Most expensive egress but integrates with other AWS services. Only if you're already AWS-native.

Your plan: Start with BunnyCDN (cheapest, full control). Add Cloudflare Stream later if you want to offload transcoding.

Complete nginx.conf

worker_processes auto;

    worker_connections 1024;
}

## ─── RTMP Block (port 1935) ─────────────────────────
rtmp {
    server {
        listen 1935;
        chunk_size 4096;

        application live {
            live on;
            record off;

            # Verify the stream key with your API before allowing
            on_publish http://127.0.0.1:4000/api/stream/auth;
            on_publish_done http://127.0.0.1:4000/api/stream/end;

            # Trigger FFmpeg to start HLS transcoding
            exec ffmpeg -i rtmp://127.0.0.1/live/$name
                -map 0:v -map 0:a
                -c:v libx264 -c:a aac
                -b:v 2500k -s 1280x720 -f flv
                rtmp://127.0.0.1/hls/$name_720p

                -map 0:v -map 0:a
                -c:v libx264 -c:a aac
                -b:v 800k -s 854x480 -f flv
                rtmp://127.0.0.1/hls/$name_480p

                -map 0:v -map 0:a
                -c:v libx264 -c:a aac
                -b:v 400k -s 640x360 -f flv
                rtmp://127.0.0.1/hls/$name_360p;
        }

        # This application receives the transcoded streams from FFmpeg
        application hls {
            live on;
            record off;

            # Convert to HLS segments
            hls on;
            hls_path /var/www/hls;
            hls_fragment 2s;          # 2-second segments
            hls_playlist_length 10s;  # Keep last 5 segments

            # Create multi-quality master playlist
            hls_variant _720p BANDWIDTH=2628000,RESOLUTION=1280x720;
            hls_variant _480p BANDWIDTH=864000,RESOLUTION=854x480;
            hls_variant _360p BANDWIDTH=432000,RESOLUTION=640x360;
        }
    }
}

## ─── HTTP Block (ports 80 + 443) ─────────────────────
http {
    include mime.types;
    default_type application/octet-stream;
    sendfile on;
    keepalive_timeout 65;

    # Allow large video file handling
    client_max_body_size 500M;

    server {
        listen 80;
        server_name yoursite.com www.yoursite.com;

        # Redirect all HTTP → HTTPS
        return 301 https://$host$request_uri;
    }

    server {
        listen 443 ssl;
        server_name yoursite.com www.yoursite.com;

        # SSL certs from Let's Encrypt (certbot fills these)
        ssl_certificate /etc/letsencrypt/live/yoursite.com/fullchain.pem;
        ssl_certificate_key /etc/letsencrypt/live/yoursite.com/privkey.pem;

        # Serve HLS files directly from disk
        location /hls {
            types {
                application/vnd.apple.mpegurl m3u8;
                video/mp2t ts;
            }
            alias /var/www/hls;
            add_header Cache-Control no-cache;
            add_header Access-Control-Allow-Origin *;
        }

        # Proxy Next.js app
        location / {
            proxy_pass http://127.0.0.1:3000;
            proxy_http_version 1.1;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection 'upgrade';
            proxy_set_header Host $host;
            proxy_cache_bypass $http_upgrade;
        }

        # Proxy Node.js API
        location /api {
            proxy_pass http://127.0.0.1:4000;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
        }

        # WebSocket for live chat
        location /socket.io {
            proxy_pass http://127.0.0.1:4000;
            proxy_http_version 1.1;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection "upgrade";
        }
    }
}

Phase 4 · Build

Stream ingest pipeline

The backend API that validates stream keys and tracks live streams.

How stream key auth works

When OBS connects to Nginx, Nginx calls your API's /api/stream/auth endpoint. Your API checks the stream key against the database. Return 2xx = allow, 4xx = reject.

javascriptserver/routes/stream.js — stream auth + lifecycle
const express = require('express');
const router = express.Router();
const { Pool } = require('pg');
const redis = require('../redis');

const db = new Pool({ connectionString: process.env.DATABASE_URL });

/**
 * Called by Nginx when OBS connects and starts streaming.
 * Nginx sends: POST /api/stream/auth with body: name=STREAM_KEY
 */
router.post('/stream/auth', async (req, res) => {
  const { name: streamKey } = req.body;

  if (!streamKey) return res.status(400).send('No stream key');

  try {
    // Look up user by stream key
    const { rows } = await db.query(
      'SELECT id, username FROM users WHERE stream_key = $1',
      [streamKey]
    );

    if (rows.length === 0) {
      console.log(`Rejected unknown key: ${streamKey}`);
      return res.status(401).send('Invalid stream key');
    }

    const user = rows[0];

    // Mark stream as live in Redis (fast, real-time)
    await redis.set(`stream:${user.id}:live`, 'true', 'EX', 86400);
    await redis.set(`stream:${user.id}:key`, streamKey, 'EX', 86400);

    // Update stream start time in PostgreSQL
    await db.query(
      'UPDATE streams SET started_at = NOW(), is_live = true WHERE user_id = $1',
      [user.id]
    );

    console.log(`✓ Stream started: @${user.username}`);
    res.status(200).send('OK');

  } catch (err) {
    console.error('Stream auth error:', err);
    res.status(500).send('Server error');
  }
});

/**
 * Called by Nginx when OBS disconnects / stops streaming.
 */
router.post('/stream/end', async (req, res) => {
  const { name: streamKey } = req.body;

  try {
    const { rows } = await db.query(
      'SELECT id FROM users WHERE stream_key = $1', [streamKey]
    );

    if (rows.length > 0) {
      const userId = rows[0].id;
      await redis.del(`stream:${userId}:live`);
      await db.query(
        'UPDATE streams SET ended_at = NOW(), is_live = false WHERE user_id = $1',
        [userId]
      );
    }

    res.status(200).send('OK');
  } catch (err) {
    res.status(500).send('Error');
  }
});

module.exports = router;

FFmpeg transcoding

The command that converts one RTMP stream into multiple quality HLS streams.

The full FFmpeg command

bashMulti-bitrate HLS transcoding command
ffmpeg \
  -i rtmp://localhost/live/STREAM_KEY \    # Input: RTMP from Nginx
  
  # ── Quality 1: 1080p ──────────────────────────────
  -map 0:v -map 0:a                          \  # Map video+audio
  -c:v libx264 -c:a aac                      \  # H.264 video, AAC audio
  -b:v 4000k -s 1920x1080                    \  # 4 Mbps, 1080p
  -preset veryfast                            \  # Encode speed (faster = less CPU, lower quality)
  -profile:v high -level 4.1                 \  # H.264 profile
  -g 60 -keyint_min 60                       \  # Keyframe every 2s at 30fps
  -hls_time 2 -hls_list_size 5              \  # 2s segments, keep last 5
  -hls_flags delete_segments                 \  # Delete old segments
  -hls_segment_filename /var/www/hls/STREAM_KEY/1080p_%04d.ts \
  /var/www/hls/STREAM_KEY/1080p.m3u8        \

  # ── Quality 2: 720p ───────────────────────────────

  -c:v libx264 -c:a aac                      \

const path = require('path');

function createMasterPlaylist(streamKey) {

  fs.mkdirSync(dir, { recursive: true });

  const master = `#EXTM3U
#EXT-X-VERSION:3
#EXT-X-STREAM-INF:BANDWIDTH=4200000,RESOLUTION=1920x1080,NAME="1080p"
1080p.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=2628000,RESOLUTION=1280x720,NAME="720p"
720p.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=864000,RESOLUTION=854x480,NAME="480p"
480p.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=432000,RESOLUTION=640x360,NAME="360p"

'use client';
import { useEffect, useRef, useState, useCallback } from 'react';
import Hls from 'hls.js';

export default function VideoPlayer({ streamKey, channelName }) {
  const videoRef = useRef(null);
  const hlsRef = useRef(null);
  const [levels, setLevels] = useState([]);
  const [currentLevel, setCurrentLevel] = useState(-1); // -1 = auto
  const [isPlaying, setIsPlaying] = useState(false);
  const [isLive, setIsLive] = useState(false);
  const [stats, setStats] = useState({ bandwidth: 0, latency: 0 });

  const src = `/hls/${streamKey}/master.m3u8`;

  useEffect(() => {
    if (!videoRef.current) return;

    if (Hls.isSupported()) {
      const hls = new Hls({
        enableWorker: true,
        lowLatencyMode: false,     // Set true for LL-HLS later
        backBufferLength: 30,
        liveMaxLatencyDuration: 30,
        liveSyncDuration: 3,
      });

      hlsRef.current = hls;
      hls.loadSource(src);
      hls.attachMedia(videoRef.current);

      // When HLS is ready to play
      hls.on(Hls.Events.MANIFEST_PARSED, (_, data) => {
        setLevels(data.levels);
        setIsLive(true);
        videoRef.current.play().catch(console.error);
      });

      // Track current quality level
      hls.on(Hls.Events.LEVEL_SWITCHED, (_, data) => {
        setCurrentLevel(data.level);
      });

      // Network stats
      hls.on(Hls.Events.FRAG_LOADED, (_, data) => {
        setStats({
          bandwidth: Math.round(data.frag.stats.bwEstimate / 1000),
          latency: Math.round(data.frag.stats.loading.end - data.frag.stats.loading.start)
        });
      });

    } else if (videoRef.current.canPlayType('application/vnd.apple.mpegurl')) {
      // Safari native HLS support
      videoRef.current.src = src;
    }

    return () => hlsRef.current?.destroy();
  }, [src]);

  const setQuality = (level) => {
    if (hlsRef.current) {
      hlsRef.current.currentLevel = level;
      setCurrentLevel(level);
    }
  };

  return (
    <div className="relative bg-black rounded-lg overflow-hidden">
      <video
        ref={videoRef}
        className="w-full aspect-video"
        controls
        playsInline
        onPlay={() => setIsPlaying(true)}
        onPause={() => setIsPlaying(false)}
      />

      <{/* Live badge */}>
      {isLive && (
        <div className="absolute top-3 left-3 bg-red-600 text-white text-xs font-bold px-2 py-1 rounded">
          ⬤ LIVE
        </div>
      )}

      <{/* Quality selector */}>
      <div className="absolute top-3 right-3 flex gap-1">
        <button
          onClick={() => setQuality(-1)}
          className={`text-xs px-2 py-1 rounded ${currentLevel === -1 ? 'bg-purple-600' : 'bg-black/60'} text-white`}
        >Auto</button>
        {levels.map((level, i) => (
          <button key={i} onClick={() => setQuality(i)}
            className={`text-xs px-2 py-1 rounded ${currentLevel === i ? 'bg-purple-600' : 'bg-black/60'} text-white`}
          >
            {level.height}p
          </button>
        ))}
      </div>

      <{/* Stats bar */}>
      <div className="absolute bottom-12 left-3 text-xs text-white/50">
        {stats.bandwidth > 0 && `${stats.bandwidth} Kbps`}
      </div>
    </div>
  );
}

Live chat with WebSocket

Real-time chat using Socket.io — viewer counts, messages, and moderation.

javascriptserver/socket.js — Socket.io chat server
const { Server } = require('socket.io');
const redis = require('./redis');

function initSocket(httpServer) {
  const io = new Server(httpServer, {
    cors: { origin: 'https://yoursite.com', methods: ['GET', 'POST'] }
  });

  io.on('connection', async (socket) => {
    const { channelId, username } = socket.handshake.query;
    const room = `channel:${channelId}`;

    // Join the channel room
    socket.join(room);

    // Increment viewer count in Redis
    const viewers = await redis.incr(`viewers:${channelId}`);
    io.to(room).emit('viewerCount', viewers);

    // Send last 50 messages (from Redis list)
    const history = await redis.lrange(`chat:${channelId}`, -50, -1);
    socket.emit('chatHistory', history.map(m => JSON.parse(m)));

    // Handle incoming chat message
    socket.on('chat:message', async ({ message }) => {
      if (!message || message.trim().length === 0) return;
      if (message.length > 200) return; // max message length

      const msg = {
        id: Date.now(),
        username: username || 'Guest',
        message: message.trim(),
        timestamp: new Date().toISOString()
      };

      // Store in Redis (keep last 100 messages)
      await redis.rpush(`chat:${channelId}`, JSON.stringify(msg));
      await redis.ltrim(`chat:${channelId}`, -100, -1);

      // Broadcast to everyone in the channel room
      io.to(room).emit('chat:message', msg);
    });

    // When viewer leaves
    socket.on('disconnect', async () => {
      const count = await redis.decr(`viewers:${channelId}`);
      io.to(room).emit('viewerCount', Math.max(0, count));
    });
  });

  return io;
}

module.exports = initSocket;

'use client';
import { useState, useEffect, useRef } from 'react';
import { io } from 'socket.io-client';

export default function LiveChat({ channelId }) {
  const [messages, setMessages] = useState([]);
  const [viewers, setViewers] = useState(0);
  const [input, setInput] = useState('');
  const socketRef = useRef(null);
  const bottomRef = useRef(null);

  useEffect(() => {
    const socket = io(process.env.NEXT_PUBLIC_API_URL, {
      query: { channelId, username: 'Viewer' } // Pass real username from auth
    });
    socketRef.current = socket;

    socket.on('chatHistory', (history) => setMessages(history));
    socket.on('chat:message', (msg) => setMessages(prev => [...prev, msg]));
    socket.on('viewerCount', (count) => setViewers(count));

    return () => socket.disconnect();
  }, [channelId]);

  useEffect(() => {
    bottomRef.current?.scrollIntoView({ behavior: 'smooth' });
  }, [messages]);

  const sendMessage = () => {
    if (!input.trim()) return;
    socketRef.current?.emit('chat:message', { message: input });
    setInput('');
  };

  return (
    <div className="flex flex-col h-full bg-gray-900">
      <div className="p-3 border-b border-gray-800 text-sm font-semibold text-gray-300">
        Live Chat · {viewers} viewers
      </div>
      <div className="flex-1 overflow-y-auto p-3 space-y-2">
        {messages.map((msg) => (
          <div key={msg.id} className="text-sm">
            <span className="font-semibold text-purple-400">{msg.username}</span>
            <span className="text-gray-300 ml-2">{msg.message}</span>
          </div>
        ))}
        <div ref={bottomRef} />
      </div>
      <div className="p-3 border-t border-gray-800 flex gap-2">
        <input
          value={input}
          onChange={e => setInput(e.target.value)}
          onKeyDown={e => e.key === 'Enter' && sendMessage()}
          placeholder="Send a message..."
          className="flex-1 bg-gray-800 text-white text-sm rounded px-3 py-2 outline-none"
        />
        <button onClick={sendMessage}
          className="bg-purple-600 text-white px-3 py-2 rounded text-sm font-semibold"
        >Send</button>
      </div>
    </div>
  );
}

router.post('/auth/register', async (req, res) => {
  const { username, email, password } = req.body;

  // Hash password — NEVER store plain text passwords
  const hashedPassword = await bcrypt.hash(password, 12);

  // Generate unique stream key
  const streamKey = uuidv4().replace(/-/g, '').slice(0, 24);

  const { rows } = await db.query(
    `INSERT INTO users (username, email, password, stream_key)
     VALUES ($1, $2, $3, $4)
     RETURNING id, username, stream_key`,
    [username, email, hashedPassword, streamKey]
  );

  const token = jwt.sign(
    { userId: rows[0].id },
    process.env.JWT_SECRET,
    { expiresIn: '30d' }
  );

  res.json({ token, user: rows[0] });
});

Scaling & cost management

When to upgrade, what costs to watch, and how the big platforms do it.

Cost estimate at different scales

ScaleConcurrent streamsViewersEstimated cost
Startup 1–2 <100 €10–20/mo (VPS + domain)
Small 2–5 100–1,000 €30–60/mo (bigger VPS + CDN)
Medium 5–20 1,000–10,000 €150–400/mo (dedicated + CDN)
Large 20+ 10,000+ €1,000+/mo (cluster + managed CDN)

When to upgrade what

FFmpeg transcoding is CPU-intensive. When you see CPU consistently above 80%, you have options:

  • Upgrade to a bigger VPS (4→8→16 vCPU)
  • Use hardware encoding: -c:v h264_nvenc (NVIDIA GPU) instead of libx264 — 10x faster
  • Offload transcoding to a dedicated transcoding cluster
  • Use Mux or api.video — they handle transcoding for you

The biggest scaling cost is bandwidth. Serving 1,000 viewers 720p video at 2.5 Mbps = 2.5 Gbps out. This is why CDNs exist.

Your CDN pays for egress at bulk rates. Without CDN, your VPS pays retail rates. Always serve HLS via CDN — never directly from your origin.

BunnyCDN at $0.01/GB is excellent value. At 10TB/month, that's $100. A VPS serving that traffic directly would be much more expensive or simply overloaded.

A single Node.js Socket.io server can handle ~10,000 concurrent connections. For more:

  • Use Socket.io with Redis adapter (pub/sub across multiple processes)
  • Migrate to a dedicated chat service like Stream (the chat API company)
  • Or use Ably/Pusher for managed WebSocket infrastructure

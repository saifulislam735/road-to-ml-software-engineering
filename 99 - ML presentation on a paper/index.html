── 1. THE REAL-WORLD PROBLEM ─────────────────────────────────────────

Iron is the most widely used metal on Earth.
It is converted into STEEL and used in:
  → Automotive   → Aviation   → Construction   → Railways   → Pipes

ROLLING PROCESS:
  Steel slabs are passed between two rotating rollers.
  Compression force squeezes the steel into thin sheets
  of desired thickness.

  ┌─────────────┐
  │   ROLLER    │ ← rotating
  │═════════════│
  │  Steel slab │ → becomes thin plate
  │═════════════│
  │   ROLLER    │ ← rotating
  └─────────────┘

PROBLEM:
  During rolling, if temperature, speed, or roller gap is
  not perfectly controlled → DEFECTS appear on the surface.

Common defects after rolling:
  ● Cracks          ● Scratches (Z-Scratch, K-Scratch)
  ● Bumps           ● Stains
  ● Corrosion       ● Pastry (rough surface)
  ● Dirtiness       ● Uneven elongation

WHY IS DETECTION IMPORTANT?
  → Defective steel used in automotive/aviation = safety risk
  → Defects reduce market value of products
  → Catching defects early saves cost
  → Manual visual inspection is slow and error-prone

── 4. THE FOUR ML ALGORITHMS USED ────────────────────────────────────

A. LOGISTIC REGRESSION (LR)
─────────────────────────────
Concept:
  Uses a SIGMOID function to estimate probability.
  Sigmoid formula: σ(z) = 1 / (1 + e^(-z))
  Output is always between 0 and 1.
  Compare to threshold (0.5) → decide class.

For multi-class (7 classes here):
  Uses "One-vs-Rest" or "Softmax" extension.

Strength  : Simple, fast, interpretable
Weakness  : Cannot learn non-linear boundaries well
Result    : Accuracy = 74.44%

B. DECISION TREE (DT)
─────────────────────────
Concept:
  Builds a tree structure by splitting data at each node.
  Splitting criterion: Gini Impurity or Information Gain.

  Example:
  [Root] Is Pixels_Area > 500?
         YES → [Node] Is Luminosity_Index > 0.3?
                       YES → Defect = Bumps
                       NO  → Defect = K_Scratch
         NO  → Defect = Pastry

Strength  : Interpretable, handles nonlinear data
Weakness  : Overfits easily (memorizes training data)
Result    : Accuracy = 77.77%

C. SUPPORT VECTOR MACHINE (SVM)
─────────────────────────────────
Concept:
  Finds the OPTIMAL HYPERPLANE that maximizes margin
  between classes.

  Margin = distance between hyperplane and nearest points
           (called Support Vectors).

  Kernel trick: Projects data to higher dimensions so
  linearly inseparable data becomes separable.
  Common kernels: Linear, RBF (Radial Basis Function), Polynomial.

Strength  : Works well in high-dimensional spaces, good generalization
Weakness  : Slow on large data, sensitive to parameters (C, gamma)
Result    : Accuracy = 74.44%

D. RANDOM FOREST (RF)
─────────────────────────
Concept:
  An ENSEMBLE method — combines many Decision Trees.

  How it works (Bagging):
  Step 1: Create N random subsets of training data (Bootstrap Sampling)
  Step 2: Train one Decision Tree on each subset
  Step 3: Each tree uses a random subset of features at each split
  Step 4: Final prediction = MAJORITY VOTE of all trees

  Example (5 trees):
  Tree1 → K_Scratch
  Tree2 → K_Scratch
  Tree3 → Bumps
  Tree4 → K_Scratch
  Tree5 → K_Scratch
  VOTE  → K_Scratch ✔

  Why better than single DT?
  → Reduces VARIANCE (overfitting)
  → Different trees see different data → diverse opinions
  → Errors of individual trees cancel out

Strength  : Most accurate, robust, handles imbalanced/noisy data
Weakness  : Less interpretable, slower to train than single DT
Result    : Accuracy = 79.44%  ← BEST MODEL

── 5. PERFORMANCE METRICS ─────────────────────────────────────────────

Given confusion matrix terms:
  TP = True Positive  (predicted correctly as positive)
  TN = True Negative  (predicted correctly as negative)
  FP = False Positive (predicted positive, actually negative)
  FN = False Negative (predicted negative, actually positive)

Metrics:
  Accuracy  = (TP + TN) / (TP + TN + FP + FN) × 100
            → Overall % of correct predictions

  Precision = TP / (TP + FP)
            → Of all predicted positives, how many are real?
            → Reduces false alarms

  Recall    = TP / (TP + FN)
            → Of all actual positives, how many did we catch?
            → Reduces missed detections

  F1 Score  = 2 × (Precision × Recall) / (Precision + Recall)
            → Harmonic mean → balanced measure

For MULTI-CLASS problems, two averaging methods:
  Macro avg    → Equal weight to all classes (good for imbalance analysis)
  Weighted avg → Weight by class sample count (reflects real distribution)

SLIDE 08 Model 1 — Logistic Regression (LR) 
WHAT IS ON THIS SLIDE?
  3 info sections:

  01 Core Idea:
     Probabilistic linear classifier using a sigmoid function.

  02 Characteristics:
     Simple, interpretable, fast training,
     suited for linear boundaries.

  03 Weaknesses & Result:
     Limited for complex nonlinear data.
     Accuracy: 74.44%

  Figure: Sigmoid curve (S-shaped function from 0 to 1)

WHAT = What is Logistic Regression?
  Despite the name "regression," it is a CLASSIFICATION algorithm.

  Formula:
    z = w₁x₁ + w₂x₂ + ... + w₂₇x₂₇ + b  (linear combination)
    σ(z) = 1 / (1 + e^(-z))               (sigmoid function)
    Output = probability of belonging to a class

  For our problem (7 classes):
    Uses One-vs-Rest strategy:
    → Trains 7 binary classifiers (each: "is this class X vs not X?")
    → Predicts class with highest probability

WHY was LR included?
  → It is the SIMPLEST baseline model
  → Fast to train, easy to explain to engineers
  → If it performs well → no need for complex models
  → Good for benchmarking

HOW does the sigmoid work on this data?
  Each of 27 features gets a weight (w).
  Training = finding the best weights via gradient descent
  to minimize cross-entropy loss.

  The sigmoid maps any real number → (0,1) probability.
  Values above 0.5 → predicted as positive class.

WHY did LR get only 74.44%?
  Steel defect patterns in 27D feature space are NON-LINEAR.
  LR can only draw a straight hyperplane boundary.
  → Complex curved boundaries between Bumps vs K_Scratch
    cannot be captured by a linear model.
  → LR fails to distinguish similar-looking defects.

KEY TAKEAWAY FROM SLIDE 8:
  LR = baseline model. 74.44% means the problem is NOT linearly separable.
  More powerful models (nonlinear) are needed.
SLIDE 09 Model 2 — Support Vector Machine (SVM) 
WHAT IS ON THIS SLIDE?
  3 sections:

  Core Idea:
    Finds optimal separating hyperplane with maximum margin.

  Characteristics:
    → Maximizes margin between classes
    → Effective in high-dimensional space
    → Uses kernel trick for nonlinear boundaries

  Advantages & Weaknesses:
    ✔ Strong theoretical foundation
    ✔ Good generalization
    ✖ Computationally expensive
    ✖ Sensitive to parameter selection (C, gamma)

  Figure: Kernel trick illustration (data lifted to 3D space)

WHAT = What is SVM?
  SVM finds the MAXIMUM MARGIN HYPERPLANE:
  The plane that separates classes with the largest "gap."

  Support Vectors = data points closest to the hyperplane.
  These are the most important/difficult samples.

  Margin = 2 / ||w||
  SVM maximizes margin = minimizes ||w||

  Kernel Trick:
  If data is not linearly separable in original space,
  kernel function K(xᵢ, xⱼ) maps data to higher-dimensional space
  where it BECOMES linearly separable.
  Common kernels:
    Linear   : K(x,z) = x·z
    RBF      : K(x,z) = exp(-γ||x-z||²)  ← most common
    Polynomial: K(x,z) = (x·z + 1)^d

WHY was SVM expected to perform well?
  27 features = relatively high-dimensional space
  SVM is theoretically strong in high-dimensional spaces.
  With RBF kernel, can model complex nonlinear boundaries.

WHY did SVM also get only 74.44%?
  Possible reasons:
  → Default hyperparameters were used (C=1, gamma='scale')
  → No hyperparameter tuning (Grid Search / Random Search)
  → Imbalanced classes affect decision boundary
  → Multi-class SVM (One-vs-One) = 21 binary classifiers for 7 classes
    → complex, and errors compound

HOW is SVM different from LR?
  LR   → minimizes log loss (probabilistic)
  SVM  → maximizes margin (geometric, distance-based)
  LR   → gives probability scores
  SVM  → gives hard class boundaries
  Both achieved same 74.44% → both struggling with this nonlinear data

KEY TAKEAWAY FROM SLIDE 9:
  SVM is theoretically powerful but needs proper tuning.
  Default settings gave same result as LR → suggests hyperparameter
  optimization would improve SVM significantly.
SLIDE 10 Model 3 — Decision Tree (DT) 
WHAT IS ON THIS SLIDE?
  3 sections:

  Core Idea:
    Hierarchical, feature-based splitting into branches and leaves.

  Strengths:
    Interpretable, captures nonlinear relationships, easy to visualize.

  Limitations & Result:
    Prone to overfitting and noise sensitivity.
    Accuracy: 77.77%

  Figure: Decision tree illustration with job offer example

WHAT = What is Decision Tree?
  A tree-like model where:
  ● ROOT NODE = first split (most important feature)
  ● INTERNAL NODES = decision points (feature threshold tests)
  ● LEAF NODES = final class predictions

  How splitting works:
  At each node, find the feature and threshold that best separates
  the classes using:
    Gini Impurity = 1 - Σ(pᵢ²)
    → Measures how "mixed" the classes are
    → Lower Gini = purer = better split

  Example for our steel data:
  [Root] Pixels_Area > 300?
    YES → [Node] Luminosity_Index < 0.5?
           YES → K_Scratch (leaf)
           NO  → Bumps (leaf)
    NO  → [Node] Log_X_Index > 1.2?
           YES → Z_Scratch (leaf)
           NO  → Other_Faults (leaf)

WHY did DT outperform LR and SVM (74.44% → 77.77%)?
  → DT naturally handles NONLINEAR boundaries
  → Can split in complex ways across 27 features
  → Does not assume any distribution of data

WHY is DT still not the best?
  OVERFITTING:
  → A deep DT memorizes training data perfectly
  → But performs poorly on unseen test data
  → Single DT has HIGH VARIANCE

  Noise sensitivity:
  → Small changes in training data → completely different tree structure
  → Not stable/robust enough

HOW does RF fix DT's problems?
  RF trains MANY DTs on different random subsets.
  → Each DT overfits differently
  → AVERAGING their votes cancels out individual overfitting
  → Result: lower variance, better generalization

KEY TAKEAWAY FROM SLIDE 10:
  DT at 77.77% beats LR/SVM because it handles nonlinearity.
  But overfitting limits it. Random Forest (an ensemble of DTs) solves this.
SLIDE 11 Model 4 — Random Forest (RF) 
WHAT IS ON THIS SLIDE?
  3 sections:

  Core Idea:
    Ensemble of multiple Decision Trees.

  Characteristics:
    → Uses bagging and random feature selection
    → Combines predictions from many trees

  Advantages:
    → Reduced overfitting
    → Better generalization
    → Robust performance

  Figure: Random Forest diagram showing multiple trees → Bagging → Output

WHAT = What is Random Forest exactly?
  RF = BAGGING + RANDOM FEATURE SELECTION + VOTING

  BAGGING (Bootstrap Aggregating):
  Step 1: From 1844 training samples, create N bootstrap samples
          (randomly pick 1844 samples WITH REPLACEMENT → some repeated)
  Step 2: Train one DT on each bootstrap sample
  Step 3: At each split in each DT, only consider √27 ≈ 5 random features
          (not all 27) → this ensures trees are DIVERSE
  Step 4: Collect all N trees

  PREDICTION:
  For a new test sample:
  → Feed it to all N trees
  → Each tree gives one vote
  → Final class = class with most votes (majority voting)

WHY does RF outperform DT?
  BIAS-VARIANCE TRADEOFF:
  Single DT: low bias, HIGH variance (overfits)
  RF: low bias, LOW variance (because trees are averaged)

  Mathematical insight:
  If N trees each have error rate ε and are independent:
  Combined error ≈ ε/√N → reduces with more trees

  Random feature selection ensures trees are NOT correlated.
  → Different trees make different mistakes
  → Voting cancels errors

HOW is RF better for this imbalanced dataset?
  Each bootstrap sample is random → minority classes (Dirtiness: 55 samples)

WHAT = What do these numbers mean?

  ACCURACY (79.44% for RF):
  → Of 97 test samples, RF correctly predicted ≈77 of them
  → 20 were misclassified

  PRECISION (0.87 macro for RF):
  → When RF predicts class X, it is correct 87% of the time
  → High precision = fewer false alarms
  → Very important in steel industry (don't want to reject good steel)

  RECALL (0.79 macro for RF):
  → Of all actual class X samples, RF correctly finds 79% of them
  → High recall = fewer missed defects
  → Very important for safety (don't want to miss a real defect)

  F1 SCORE (0.82 macro for RF):
  → Balances both precision and recall
  → 0.82 = good balance → RF catches defects without too many false alarms

WHY is Macro average used here?
  Macro avg = compute metric for each class, then take simple average.
  → Gives EQUAL WEIGHT to each class, including minority classes.
  → If weighted avg used, small classes like Dirtiness (55 samples)
    would barely affect the score.
  → Macro avg reveals whether the model also handles rare defects well.

HOW to interpret LR vs SVM same accuracy?

  SVM: same numbers → almost identical decision boundary behavior
  Both are limited by their linear/kernel approach without proper tuning.

WHAT = What is a confusion matrix?
  A 7×7 grid where:
  → ROWS = Actual class labels
  → COLUMNS = Predicted class labels
  → Diagonal values = correct predictions (TP for each class)
  → Off-diagonal values = misclassifications

  For our 7-class problem:
        Predicted:  Bumps  Dirt  K_Sc  Other  Past  Stain  Z_Sc
  Actual Bumps:      31     0     0     12     1     0      0
  Actual Dirtiness:   0     3     0      0     0     0      0
  Actual K_Scratch:   0     0    40      0     0     0      0
  Actual Other_Flt:   9     0     0     38     0     0      1
  ...

  The diagonal (31, 3, 40, 38...) = correct predictions
  Off-diagonal values = confusion between classes

WHY analyze confusion matrix?
  Accuracy alone hides class-specific failures.
  Example: If K_Scratch always predicted correctly (40/40)
  but Dirtiness often missed (only 3/7 correct)
  → Accuracy looks fine but Dirtiness detection is poor.

  For industrial use:
  → Need to know WHICH defects are being missed
  → Some misclassifications are worse than others
    (e.g., missing a crack = catastrophic)
    (e.g., misclassifying a stain as dirtiness = acceptable)

HOW to read RF confusion matrix?
  RF confusion matrix shows:
  ● K_Scratch: almost perfectly detected (40/40 correct)
  ● Z_Scratch: 14/17 correct
  ● Bumps: 31/44 correct — some confused with Other_Faults (12 errors)
  ● Other_Faults: 38/47 — some confused with Bumps (9 errors)
  
  Bumps ↔ Other_Faults confusion is the most common error.
  Reason: These two classes may have overlapping geometric features
          (similar pixel area, similar edge indices).

KEY TAKEAWAY FROM SLIDE 13:
  The confusion matrix tells us WHERE the model struggles.
  RF is strongest overall, but Bumps vs Other_Faults confusion
  suggests these classes need more distinctive features or more data.

WHAT = What is being critiqued here?
  This slide is the HONEST SELF-ASSESSMENT of the paper.
  Good research acknowledges its own limitations.

WHY is 79.44% potentially insufficient?
  Safety-critical applications (aerospace, automotive) require
  accuracy of 95%+ or near-zero missed-defect rates.
  20% error rate = 1 in 5 defective plates might be missed.
  In mass production: if 10,000 plates produced/day
  → ~2000 defective plates pass inspection undetected → catastrophic.

WHY is 5% test split a problem?
  97 test samples for 7 classes = ~14 samples per class on average.
  Statistical significance is questionable.
  Example: Dirtiness might have only 3-4 test samples.
  One wrong prediction = 25% error in that class.
  Solution: k-fold cross-validation (k=5 or 10) would be better.

WHY no deep learning comparison?
  The paper intentionally focuses on CLASSICAL ML.
  But a CNN on the raw images (rather than extracted features)
  would likely achieve 90%+ accuracy.
  Papers like Zhang et al. (2020) used infrared + ML and got better results.

WHY is class imbalance not addressed?
  Techniques like:
  ● SMOTE (Synthetic Minority Over-sampling Technique)
  ● Class weights in model training
  ● Undersampling majority classes
  Would help the model better learn minority classes.
  Paper does not explore these — a significant gap.

KEY TAKEAWAY FROM SLIDE 14:
  This paper is a GOOD STARTING POINT, not a final solution.
  RF at 79.44% is the best classical ML baseline.
  Future work should: cross-validate, address imbalance, try deep learning.
